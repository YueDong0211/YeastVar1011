# Database resources in the marker workspace

The data-resource directory prepares traceable annotation and interpretation inputs. The workstation's marker catalogue stores selected, source-linked records; it is not a mirror of every linked database. This directory performs no external fetch, batch gene query, file upload or automatic database import. Links open only after a user follows them.

The module is `dist/database-hub-v24.js`, styled by `dist/database-hub-v24.css`. `window.YV_DATABASE_HUB.page()` supplies the marker workspace's resource tab, and `text('title')` supplies its localized title. Chinese, English, French, Spanish and Basque are supported. Search combines with research-use and catalogue-status filters.

## Resources and fields

Official sources were checked on 17 October 2026. Version numbers and database-wide record totals are deliberately not copied into the interface; imported coverage is derived from the loaded catalogue.

The directory does not claim continuous service availability.

## Local status and counts

`resources()` derives status every time from `YV_APP.data().markers` rather than assuming that an external source has been integrated:

- SGD matches local source ID `sgd`. Its coverage counts unique catalogue records with an SGD accession and a retained systematic identifier or SGD record link.
- GO matches `go_gaf`, `go_obo` and `sgd_slim`. Coverage counts unique records containing GO/slim entries or the corresponding GO evidence relationships.
- An imported status requires a matched source and nonzero covered records. These counts describe local gene coverage, not the full source database or the number of GO annotations.
- All other entries remain `linked`. Bibliographic references to studies, database names or a selected research direction do not establish imported database records.

The ontology is not itself a list of measured genes. The combined GO card therefore presents gene coverage across local annotations/slim assignments, with its separate source records available in the details.

## Gene links and import preparation

The gene-link input requires an exact catalogue symbol, systematic identifier, SGD accession or unambiguous alias. An ambiguous or missing match creates no external gene query. The module uses an existing validated SGD record URL, or the already stored SGD accession, to open a single known record. It does not generate speculative search parameters for other databases.

The marker-panel import link opens the existing prepared-gene and assignment import workflow. It is not a parser for raw BioGRID, STRING, GAF or ComplexTab files. For a new resource, retain source release/checksum, organism, stable identifier mapping, evidence type, publication and source-specific context before converting selected relationships into local marker evidence. A strain/accessory gene that lacks a reference identity should retain its original identifier and mapping uncertainty.

### From motif profiles to a yeast ranking database

The catalogue input `yeast_motif_database` requires preparation beyond retrieving motif profiles. JASPAR and YeTFaSCo cards expose `planningInputs: ['yeast_motif_database']` so this prerequisite can be found in search. This metadata identifies a preparation source; it does not declare the requirement satisfied. Both cards remain `linked` and add no imported gene coverage.

Retain a reproducible manifest of: the source release and individual profile versions; S. cerevisiae versus transferred fungal profiles; TF/systematic-ID mappings and confidence; PFM-to-PWM choices and background base frequencies; the exact reference or strain genome and gene annotation; promoter/region windows, strand and overlaps; scanning software and settings; the eligible gene/region universe; and the resulting score/ranking build and motif-to-TF annotation files. A motif match is a predicted binding site, not demonstrated occupancy or a single-cell causal edge. Rank enrichment requires a defined background universe as well as the motif scores.

The [official pySCENIC requirements](https://pyscenic.readthedocs.io/en/latest/installation.html) distinguish TF lists, cisTarget ranking databases and motif annotations. The [cisTarget database-construction repository](https://github.com/aertslab/create_cisTarget_databases) documents database creation from chosen regions/sequences and motif scoring. Build and verify a yeast-compatible resource for the selected genome and identifiers; do not relabel a JASPAR MEME/PFM download or YeTFaSCo PWM collection as an immediately compatible `.feather` ranking database.

During this check, JASPAR identified its current site as release 2026 and exposed a Fungi download group. YeTFaSCo's download page selected version 1.02 and separated all profiles from expert-curated profiles. The UI does not freeze these as universally current versions; retain the actual downloaded release/version in each preparation manifest. No REST endpoint availability is asserted or required by the module.

## Verification

`node research/qa-database-hub-v24.cjs` checks the twelve entries, all five interface languages, dynamic source/coverage handling, search and combined filters, imported-versus-linked distinction, motif prerequisite discovery and preparation fields, exact unambiguous gene links, escaped search input, delegated controls, current marker shards and absence of network calls. Short ASCII acronyms use word boundaries, so matches such as `TF` inside `platform` are excluded. Browser layout review remains separate from these data and logic checks.
